影响：

1. **测不了 D.83 的两类已知失败**：短主题词的 ILIKE 命中、教材块被高考题挤掉——本轮无对应样本。
2. **样本偏长句**：15/15 都是完整需求句，检索器当前把整句当 `topic` 去做 `ILIKE`，长句几乎必然失配；
   这会真实暴露问题，但也意味着本轮基线只代表“长句形态”。
3. **教师背景缺失**：无法按教龄/年级分层；`contributor` 只能写“未记录”。
4. **无 strict target**：没有任何一条明确指向“某年某卷某题”，所以 strict 指标分母为 0；若后续教师能指出具体原题，应补 `expect.strict`。
5. **编号 11–15 缺失**：若用户手上有这 5 条，补录后可提升到 20 条并改善类别分布；没有就保持缺号，不补造。

## 6. DB 恢复后的复核与一键运行（已于 2026-11-06 执行）

### 6.1 先复核，再跑基线

1. 确认库里有平台语料：查 `knowledge_sources` / `knowledge_questions` / `knowledge_chunks` 条数
   （D.83 快照为 346 套 / 6981 题；当前是否一致需实测）。
2. 对每条 `expect.any` 做 SQL 复核，例如：

   ```sql
   SELECT count(*)
   FROM knowledge_chunks c
   JOIN knowledge_document_versions dv ON dv.id = c.document_version_id
   JOIN knowledge_sources s ON s.id = dv.source_id
   WHERE c.text_content ILIKE '%零点%';
   ```

   重点确认两件事：片段是否出现在 chunk 文本中；是否落在 `excerpt` 前 400 字内（否则判定看不中）。
3. 年份+卷别类（Q02、Q06、Q07、Q08、Q10）先确认 `knowledge_sources.year` / `exam_paper` 非空，
   再考虑把“近五年/新高考一卷”补成 `{"all":[...]}` 的 year/paper 子句。当前未写，因为元数据不可验证。
4. 逐条复核通过后，把 `expect_verified` 改为 `true`，并在 `notes` 记核验人/日期/证据；
   **没复核的条目保持 false**。首轮报告 trust 为 false 是正确状态。
5. 如补到 20 条以上或补齐 11–15，更新 `provenance.source_total` 与 `missing_numbers`。
