# 高中数学知识库 · 检索召回问题总结（给设计）

> 日期：2026-11-07  
> 数据：60 条真实教师检索问题（来自 3 位教师），其中 20 条带“精确对象”（某条定义/定理/公式/某道题）。  
> 目的：说明**用户提问后，系统为什么找不准/找不全**，以及哪些问题该由界面/交互解决，哪些是检索或数据问题。

## 0. 一句话结论

教材、真题、模拟题的数据已经基本齐了，但当前检索还**不会“按内容类型找对东西”**：

- 问“公式”，返回的是一堆高考解答题；
- 问“找一道选择题”，返回的是教材目录/小结；
- 用户说的“近五年/选择题/压轴题/基础题”，大部分没有变成真正的筛选条件，而是当成普通文字去匹配；
- 教材定义/公式和题目混在同一个结果列表里，没有类型分层。

所以现在的核心问题不是“库里没有”，而是**“有，但没在对的位置、没有按用户的条件组织出来”**。

## 1. 当前召回水平（先建立共同基线）

用 60 条教师问题测了 5 种检索方式，重点看两个指标：

- **广召回**：前 8 条里有没有相关内容（用户“能找到点东西”）；
- **精确对象**：前 8 条里有没有教师指定的那一条定义/公式/题（用户“就是它”）。

| 检索方式 | 广召回 | 精确对象 | 说明 |
| --- | ---: | ---: | --- |
| H 混合检索（当前默认） | 58/60 = 96.7% | 17/20 = 85.0% | 快，广召回好 |
| HR 混合 + 重排 | **60/60 = 100%** | **19/20 = 95.0%** | 精确对象明显更好，但每条多约 0.55 秒 API 成本 |
| V 只走向量 | 59/60 | 18/20 | 比 H 更“准”，但缺文字精确匹配 |
| T 只走文字匹配 | 44/60 | 5/20 | 中文口语/同义表达效果差 |
| L 旧检索 | 28/60 | 0/20 | 历史对照，不可用 |

**不能把这些数字当产品准确率**：只有 60 条、20 个精确对象、单次评测，而且“广召回”是宽松判定。它们只用于定位问题。

## 2. 具体召回问题（带真实例子）

### 问题 1：问“公式”，返回的是题，教材公式块根本没进候选

**例子**：教师问“导数的解答题里常用的**切线方程公式**是什么？”

- 实际返回的前 8 条**全是高考解答题**（2012–2026 的导数题），没有一条是教材里讲“导数几何意义/切线方程”的段落；
- 教材里其实有两块相关内容：
  - p73：导数 = 切线斜率；
  - p64：点斜式 `y-y0=k(x-x0)`；
- 但这两块**在召回阶段就没进前 8**，后面的重排也救不回来。

**设计含义**：问公式/定义时，结果列表不能和“找题”混排；教材公式卡应该优先出现在前面。

---

### 问题 2：问“找一道选择题/压轴题”，返回教材目录和小结

**例子**：教师问“找一道解析几何的**压轴题**”。

- 当前混合检索的前 8 条是：教材目录、本册导引、章节小结、解析几何介绍……**没有一道真正的题**；
- 只有加了重排之后，才把真正的解答题拉上来。

**设计含义**：用户说“选择题/填空题/解答题/压轴题”时，这应该是**筛选条件**，不是普通文字。结果页需要有题型筛选/标签，且默认只出题、不出教材目录。

---

### 问题 3：题型信息存在，但检索没有用它

- 库里的每道题其实有 `question_type`（单选/多选/填空/解答），但文字检索和向量检索**不按这个字段过滤**；
- 评测里我们临时给 5 条“找一道…”加了“题型 + 知识点”的判定条件，HR 的广召回才从 55/60 升到 60/60；
- 这说明：**同样的检索结果，按题型一筛就对了**——问题在交互层没有把这个条件暴露给用户/没有传给检索。

**设计含义**：搜索框下面需要“题型 chips”（选择/填空/解答/证明），或者从自然语言里自动识别并显示成可取消的 chip：“已按：选择题 ×”。

---

### 问题 4：用户说的词，和语料里的词对不上

**例子**：

- “圆锥曲线选择题里常用的**焦点弦长公式**”——教材里没有“焦点弦长公式”这个独立块；返回的是椭圆/双曲线相关题，但摘要里没有“焦点弦”三个字；
- “找几道可以用**数形结合**解的题”——语料里几乎没有“数形结合”这个字面词，系统返回了函数/几何题，但判定为“不相关”。

**设计含义**：

- 需要**同义/口语扩展**：焦点弦 → 椭圆/双曲线焦点相关；数形结合 → 图象/几何；
- 当“没有完全匹配”时，界面要能说“未找到完全匹配，以下是相近内容”，而不是给一个看起来像结果的列表；
- 这类 query 也应该允许“无结果/证据不足”状态，而不是硬凑 8 条。

---

### 问题 5：稀有词 + 年份条件互相冲突

**例子**（上一版真实问题）：教师问“**近五年**高考数学数列大题，重点筛选**递推**数列和数列求和”。

- “递推”在库里只有 26 条，且都在 2012–2015 年；
- 加上“近五年（2022–2026）”过滤后，一条都不剩；
- 但系统没有提示“近五年没有”，也没有回退到更早年份，而是返回了一堆普通数列题。

**设计含义**：

- 年份条件与稀有词冲突时，不能静默给普通结果；
- 需要分组显示：“近五年（0 条）→ 更早年份（3 条，2013–2015）”；
- 或者提供“放宽到更早年份”的按钮。

---

### 问题 6：教材定义/公式与题目混排，精确对象被挤出前 8

- 只走向量时，精确对象可以到 90%；混合检索（H）反而只有 85%——因为文字结果和题目结果一起融合时，**精确的教材块可能被题海挤下去**；
- 加 API 重排后回到 95%，但重排每条要多约 0.55 秒，且是外部 API 成本。

**设计含义**：

- 结果列表需要按对象类型分组/分层：教材定义、定理、公式、题目、解析；
- 默认排序不应该让“教材目录/章节导引”这类低价值块占据顶部；
- 公式/定义类查询，应该优先展示教材块卡片（带页码/出处）。

---

### 问题 7：知识库本身有缺口（不是检索能修的）

- “焦点弦长公式”在教材里没有独立公式块（至少当前 OCR/切块里没有）；
- 有 11 个知识点是“教师认为有内容、但词表没有合适考点”（vocab_gap）；
- 有些公式只出现在例题解答里，没有独立陈述块。

**设计含义**：

- 结果页可以标“教材暂无独立公式，以下为相关题/推导”；
- 需要维护一份“待补清单”（缺公式、缺定义、词表缺口），让编辑/教师补，而不是让检索硬凑。

## 3. 哪些问题该在哪里修

| 问题 | 检索/数据 | 界面/交互 |
| --- | --- | --- |
| 公式查询返回题目 | 加“教材公式块优先”策略 | 结果卡区分“公式/题目”，公式卡优先 |
| “找一道选择题”返回教材 | 按 `question_type` 过滤 | 题型 chips + 自动识别 |
| 焦点弦/数形结合对不上 | 同义词/知识点扩展 | “未找到完全匹配，以下是相近内容” |
| 近五年 + 递推冲突 | 年份冲突检测/回退 | 分组显示“近五年 0 条 / 更早年份 N 条” |
| 精确教材块被挤出 | 类型权重/分层检索 | 分组展示，不混排 |
| 教材缺公式 | 补数据 | “待补”标签 |
| 评测数字看起来很好 | 扩大评测集/CI | 不要把评测数字直接当产品承诺 |

## 4. 给设计的具体建议（可直接讨论）

1. **结果卡加“对象类型”**：教材定义 / 定理 / 公式 / 题目 / 解析 / 目录，各用不同视觉；用户一眼知道“找到的是什么”。
2. **搜索框下加筛选 chips**：教材 / 真题 / 模拟；选择 / 填空 / 解答 / 证明；年份段；知识点。自然语言识别出的条件要显示为可取消的 chip。
3. **公式/定义类查询走“知识卡”样式**：显示公式、定义原文、页码/出处；不要把公式查询的结果做成题卡列表。
4. **“找一道…”类查询默认只出题**：显示“已按：选择题 · 圆锥曲线”之类的条件；没有结果时给“放宽题型/年份/知识点”按钮。
5. **年份冲突分组**：近五年无结果时，明确提示并给“更早年份”分组，不静默混排。
6. **空状态/证据不足状态**：说清“为什么没找到、建议放宽哪个条件”，不要用不相关的结果填满。
7. **命中原因**：卡片上显示“命中：标题/正文/知识点/题型”，帮助教师判断可信度。
8. **待补标签**：教材缺公式/词表缺口的内容标“待补”，不要伪装成已覆盖。

## 5. 需要设计一起定的问题

1. 公式/定义类查询，结果页是“知识卡优先”还是“题卡优先”？两者如何切换？
2. “找一道…”类，默认是只出题，还是题 + 教材参考混排？如果混排，比例/分组怎么定？
3. 年份冲突（近五年 0 条）时，默认展示更早年份，还是只显示空状态 + 放宽按钮？
4. 类型 chips 是常驻，还是从自然语言识别后出现？用户能否手动取消？
5. “待补/证据不足”在结果页的视觉优先级：是弱提示，还是显著的空状态？

## 6. 评测边界（避免误读）

- 60 条问题来自 3 位教师（T01/T02/T03）；另外 4 位教师的填写版尚未纳入；
- 20 条精确对象：定义 9 / 定理 6 / 公式 5；比原计划 30 条少，主要因为“焦点弦公式无独立教材块”和“找一道…”类难以定义唯一对象；
- 单次评测、无真实用户流量、无长期跟踪；“广召回 100%”是 60/60 的评测值，不是线上准确率；
- 当前结论只用于**定位问题**，不是发布承诺。
