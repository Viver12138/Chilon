# Chilon 教师走查包

> **用途**：在 D3 页面规格冻结前，用极简线框验证七道门禁的顺序、页面的信息量、文案的可理解性。
> **对象**：2–3 位高中数学教师。
> **耗时**：每人 45–60 分钟。
> **需要**：一台电脑或打印稿（[wireframes.html](wireframes.html)）、本文件、纸笔。

------------------------------------------------------------------------

## 1. 这东西是什么，不是什么

**是**：一次设计走查。用最低保真的线框，看老师会不会在某个步骤卡住。

**不是**：可用性测试、产品演示、需求访谈。不要问“你还想要什么功能”——那会把走查变成需求会，收不到关于流程的反馈。

**判定标准**：不是“老师觉得好不好”，而是**他能不能顺畅说完一个完整任务**。说不下去的地方，就是设计问题。

------------------------------------------------------------------------

| 项 | 说明 |
| --- | --- |
| 打开 [wireframes.html](wireframes.html) | 浏览器直接打开即可。**线框里没有任何观察提示**，可以直接给老师看，不需要切换模式 |
| 观察点 | 本文件 §4.1，主持人自己看，不要念出来 |

**不要提前发给老师看线框。** 第一反应比深思熟虑后的评价有用。

## 3. 60 分钟流程

| 时间 | 内容 | 目的 |
| --- | --- | --- |
| 0–5 min | 背景说明（§3.1 逐字稿） | 建立情境，明确“你不是来评产品” |
| 5–12 min | 场景 A：从零备一节课 | 主业流程，最核心 |
| 12–20 min | 场景 B：改已有讲义 | 验证“编辑不重审计划”能否被感知 |
| 20–28 min | 场景 C：课堂小测 | 验证自动批准计划是否可接受 |
| 28–38 min | 场景 D：纸质资料 | 验证知识库这一环值不值得做 |
| 38–45 min | 反向提问（§6） | 收集我们没想到的问题 |
| 45–55 min | 整体印象与取舍（§7） | 测优先级，不测偏好 |
| 55–60 min | 收尾与致谢 | 说明后续会怎么用他的反馈 |

**内容多时可以砍成 30 分钟版**：只做场景 A 与 D，加 §7 的取舍问题。

### 3.1 开场白（照读，别临场发挥）

> 张老师，谢谢你抽时间。我这边在做一个帮老师备课的工具，现在是设计阶段，还没有做出来。
>
> 今天不是让你评这个东西好不好，因为还没做，评也没有意义。我想看的是：如果你真的要用它备明天的课，会不会在某个地方卡住、看不懂、或者觉得太麻烦。
>
> 所以我会给你看几张很粗糙的图，你就当它真的能用，边看边说说你会怎么做。卡住的地方请一定说出来，你觉得丑、觉得多余、觉得没用，都可以直说——这些比夸奖有用得多。
>
> 全程大概 45 分钟，中间可以随时打断我。

## 4. 场景卡

每张卡的做法相同：**先读情境，再指着线框问“你下一步会点什么”**，然后跟着他的操作走。

### 场景 A · 从零备一节课（核心）

> **情境**：周三晚上 9 点，明天上午第二节是高二“三角函数的图象与性质”复习课。
> **目标**：一份讲义（学习目标、定义、两道教辅例题）+ 5 道高考真题 + 2 道近期模拟题（中等难度），导出学生版。

**走线**：面板 0 → 1 → 2 → 3 → 4 → 5 → 6

**必问**（按顺序，不要跳）：
1. 现在你会先点哪里？
2. 到面板 2（计划审批）时：你能说清这一页在批准什么吗？
3. 如果系统默认替你点过这一页，你能接受吗？还是每次都想自己看一眼？
4. 假如系统说“资料里只有 2 道真题，凑不够 5 道”，你希望它什么时候告诉你、怎么告诉你？
5. 从提交到拿到文件，你能接受等多久？超过多少你就不用了？

### 场景 B · 改一份已有讲义

> **情境**：上周发布过这份讲义，今天想加一个“易错点”小节，并把第 3 题换掉。

**走线**：面板 1（新建草稿的说明）→ 4（重新检查）→ 5（再次发布）

**必问**：
1. 你觉得这次还需不需要重新批准计划？为什么？
2. 只改了两个地方就要重跑检查，你能接受吗？不能的话，你希望什么时候才检查？
3. 如果检查说你新加的例题和原有知识点冲突，你希望提示出现在哪一屏？

### 场景 C · 课堂小测

> **情境**：明天课上要一个 10 分钟的小测，学生版，5 道选择题，内容就是今天讲的正弦定理。

**走线**：面板 1 → 2（计划被自动批准，跳过）→ 4 → 6

**必问**：
1. 这次系统自动批准了计划，没让你看。你能接受吗？
2. “快”和“可控”，如果只能选一个，你选哪个？为什么？
3. 学生版里没有答案，你愿意信系统，还是想自己核一遍？

### 场景 D · 只有纸质资料

> **情境**：同事给了一本练习册，你想用第 12 页的两道题，手头只有手机拍的照片。

**走线**：面板 7

**必问**：
1. 从拍照到能引用，你能接受多久？超过多久你宁可自己手打？
2. 第 13 题被标“公式可能有误”，你会去核对吗？还是直接点确认？
3. 你希望看到原图和识别结果并排吗？

### 4.1 逐屏观察点（主持人自己看，不要念给老师）

线框里不再印任何观察提示，避免老师看到后迎合。以下按面板号列出，走查时对照着看。

| 面板 | 观察什么 |
| --- | --- |
| 0 起点 | 老师会不会问“项目是什么”？如果问了，说明这个概念没讲清。会不会直接去点“上传资料”而不是创建项目？ |
| 1 需求表单 | 有没有老师想填但表单里没有的项？哪个字段看不懂（“内容类型”？“导出用途”）？题量、难度会认真填还是一路默认？ |
| 2 计划审批 | 老师能不能主动说出这一页在批准什么（说不清 = 设计失败）。如果去掉这一页、由系统代批，他会不会不安。“将执行的检查”三项对他有意义还是噪音。 |
| 3 生成中 | “7 步”和“SymPy”看得懂吗？如果这一步要 8 分钟而不是 1 分钟，他会做什么？会不会去做别的事，回来最想看到什么？ |
| 4 检查结果 | “需要你决定”和“可以通过”同时出现，会不会困惑？会不会不看内容直接点“忽略警告”？“Validator 输出”这个证据会不会点开、点开看得懂吗？ |
| 5 发布审核 | 看到“永久不可修改”会不会犹豫，犹豫是因为怕改不了还是因为不确定内容对不对。“学生版将排除 6 个答案节点”让他放心还是想自己再核。 |
| 6 导出 | “已核对 0 个”能不能让他放心，还是他仍要下载后自己再看一遍。会先导教师版还是学生版。 |
| 7 上传纸质资料 | 最关键的负面信号：会不会说出“不如自己手打”。核对时是否需要原图与识别结果并排。 |

## 6. 反向提问

走完场景后，问这三个：

1. **“整个过程里，哪一步最让你不放心？”**
   —— 找信任缺口。不放心的地方，加证据比加确认有效。

2. **“如果只能保留三步，你留哪三步？”**
   —— 测门禁的真实优先级，比问“步骤多不多”有效。

3. **“你会怎么跟同事描述这个工具？”**
   —— 他的描述就是产品定位的实战版本。如果说成“帮我改作业的”，说明定位传达失败。

------------------------------------------------------------------------

## 7. 取舍问题（替代“你还想要什么”）

不要问功能清单，问取舍：

| 问题 | 测什么 |
| --- | --- |
| 同样一份讲义，“5 分钟但可能有一处小错”和“15 分钟但保证对”，你选哪个？ | 质量门禁的严格度是否值得 |
| 你最想在哪个环节省时间：找资料、写内容、还是检查？ | 投入优先级 |
| 如果这个工具明天消失，你会最想念它的哪一点？ | 真实价值点 |

------------------------------------------------------------------------

## 8. 归纳方法

反馈按性质分三类，处置方式完全不同。**分类错了，改法就错了。**

| 信号 | 典型话术 | 正确处置 | 错误处置 |
| --- | --- | --- | --- |
| **认知类** | “这是什么意思”“它在批准什么” | 改文案与信息层级 | 加说明弹窗（越加越乱） |
| **效率类** | “步骤太多”“太慢” | 合并交互步骤；或把任务类型默认值改成 `scoped_generation`（G3 自动通过） | 关闭门禁（破坏闭环不变量） |
| **信任类** | “我不敢信”“万一错了呢” | **增加证据展示**（出处、验证方法、排除数量） | 加确认弹窗（流程更长，信任没变） |

### 8.1 三个最容易犯的错

1. **把信任问题当效率问题**：老师说“不放心”，你加一个“我已确认”的勾选框。结果他更不放心——因为工具在让他承担判断责任，却什么证据都没给。
2. **把礼貌当认可**：老师说“挺好的”，不等于设计通过。只看他**做了什么**，不看他**说了什么**。
3. **现场就改设计**：走查中冒出的方案不成熟。记下来，回去统一处理。

### 8.2 走查后 48 小时内必须产出

- 每个场景一张填好的记录表；
- 一份“必须改”清单（只列会导致任务中断的问题）；
- 一份“待观察”清单（不确定是否要改的）；
- 一句话结论：**七道门禁的顺序，是否需要调整。**

------------------------------------------------------------------------

## 9. 你会拿到的改动长什么样

为了让反馈可追溯，每一条改动都会落到具体位置：

| 反馈类型 | 改哪里 | 分册 |
| --- | --- | --- |
| 某个状态的话看不懂 | 状态文案表 | D4 §6 |
| 某一步多余 | 交互步骤映射与点击预算 | D2 §6 |
| 计划审批不需要每次都看 | 任务类型默认值 | D2 §5 |
| 检查结果不敢信 | 证据展示区 | D3 |
| 导出前想再确认 | 发布审核页的信息项 | D3 |

**不会发生的事**：因为一次走查就关闭 G4–G7 门禁。那四道是闭环不变量，改了要重做状态机，不是调文案能解决的。

**附：主持人禁忌清单**

- ✗ 不要问“你觉得这个设计怎么样”
- ✗ 不要解释设计意图（“这里我们特意做了…”）——会污染回答
- ✗ 不要为设计辩护（“这个是因为…”）
- ✗ 不要说“这个我们后面会做”——打断他继续描述卡点
- ✗ 不要一次展示全部面板——一次一屏，跟着他的操作走
- ✓ 他说“这里有点怪”时，追问“哪里怪”“你本来以为会怎样”
- ✓ 沉默 5 秒，让他自己往下说
